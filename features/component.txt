COMPONENT.TXT — Hợp đồng từng component
Mỗi component: VAI TRÒ | VÀO | RA | LỖI PHÁT RA | KHÔNG ĐƯỢC LÀM | TEST ĐỘC LẬP

======== LÕI (fd core) ========

[C-CONNECT] fd_connect  (tiếp nhận kết nối: cam, ESP32, ...)
  VAI TRÒ : mở/đóng/giám sát kết nối, cấp địa chỉ nguồn (id, kiểu, uri)
  VÀO     : cấu hình từ fd_config (yaml/json)
  RA      : RawPacket (xem logic.ts), sự kiện trạng thái kết nối
  LỖI     : E_CONN_OPEN, E_CONN_LOST, E_CONN_TIMEOUT
  KHÔNG   : xử lí ảnh, chạy AI, quyết định vi phạm
  TEST    : workbench/connect_probe (mở nguồn, đếm gói/giây, ngắt giả)

[C-SIGNAL] fd_signal  (nhận & chuẩn hóa tín hiệu/ảnh thô)
  VAI TRÒ : gắn timestamp, frame_id, trace_id; kiểm kích thước/định dạng
  VÀO     : RawPacket   RA: SignalPacket
  LỖI     : E_SIG_BAD_FORMAT, E_SIG_EMPTY, E_SIG_TS_DRIFT
  KHÔNG   : lọc theo thuật toán, giữ trạng thái vi phạm
  TEST    : workbench/signal_check (ảnh đen, ảnh sai kích thước, ts lệch)

[C-PROCESS] fd_process  (nơi đặt thuật toán)
  QUY TẮC : 1 thuật toán = 1 file. Hàm hỗ trợ không thuộc thuật toán -> thư mục util/ riêng.
  Con:
   - baseline.*   : học khung hình chuẩn 5–10s cho 1 tài xế
   - sampler.*    : chọn frame theo fps (phân luồng frame vào hệ thống)
   - ai/          : AiAdapter (stub, yolo) — cắm vào, không chèn vào lõi
   - rules/*.*    : mỗi luật vi phạm 1 file (ví dụ: nhắm mắt, quay đầu, dùng điện thoại)
  VÀO     : SignalPacket (+ BaselineProfile)   RA: DetectionResult / ViolationEvent
  LỖI     : E_PROC_MODEL_LOAD, E_PROC_TIMEOUT, E_PROC_BAD_OUTPUT
  KHÔNG   : đọc camera, gọi server, ghi đĩa trực tiếp
  TEST    : workbench/algo_<tên> (chạy 1 thuật toán trên ảnh/video mẫu, không cần cả hệ thống)

[C-FLOW] fd_flow  (luồng dẫn: nối các fd, chỉ nối, không xử lí)
  VAI TRÒ : cây luồng (plan tree), hàng đợi theo cạnh, cache điều phối ("OS nhỏ")
  VÀO/RA  : mọi gói đi qua đây; kiểm kiểu gói ở mỗi cạnh
  LỖI     : E_FLOW_EDGE_TYPE (sai kiểu giữa A->B), E_FLOW_QUEUE_FULL, E_FLOW_NODE_DOWN
  CHỨC NĂNG: cô lập node/cạnh lỗi, phát ErrorEvent có nodePath, chạy suy giảm nếu cho phép
  KHÔNG   : sửa dữ liệu, chứa logic thuật toán
  TEST    : workbench/flow_trace (bơm gói sai kiểu -> phải chỉ đúng cạnh)

======== CÁC FD BỔ SUNG ========

[C-RESPONSE] fd_response  (phản hồi)
  VAI TRÒ : cảnh báo tại chỗ, gửi cụm frame vi phạm về server, nhận phản hồi server
  TIMELINE: buffer vòng giữ -2s trước sự kiện; t=0 bắt đầu vi phạm; ghi đến hết sự kiện
  LỖI     : E_RESP_SEND, E_RESP_NO_ACK, E_RESP_BUFFER_OVERRUN
  TEST    : workbench/response_sim (server giả chậm/rớt)

[C-DIAGNOSE] fd_diagnose  (tìm nguyên nhân)  — NGOÀI đường chạy chính
  VAI TRÒ : nhận ErrorEvent, tái hiện ở workbench, xuất hồ sơ BUG-xxx.md (nodePath, nguyên nhân, cách tái hiện)
  PHÂN LOẠI: lỗi nguồn / lỗi dữ liệu / lỗi hợp đồng giữa 2+ file / lỗi thuật toán / lỗi hiệu năng / lỗi cấu hình
  KHÔNG   : sửa code

[C-FAULTSIM] fd_faultsim  (mô phỏng lỗi)
  VAI TRÒ : bơm lỗi có kiểm soát (rớt khung, ảnh đen, trễ, mất gói, sai kiểu, prompt sai phạm vi)
  KỊCH BẢN: workbench/faults/*.yaml
  MỤC TIÊU: chứng minh hệ thống báo đúng mã + đúng nodePath

[C-REGISTRY] fd_registry  (sổ cập nhật nhánh)
  VAI TRÒ : ghi phiên bản/hợp đồng/phụ thuộc từng nhánh; khi 1 nhánh đổi, liệt kê nhánh phải test lại

[C-CONFIG] fd_config
  VAI TRÒ : yaml/json duy nhất cho địa chỉ nguồn, fps, ngưỡng, kích thước buffer, chế độ (sim|rasp)
  CHẾ ĐỘ  : mode=sim (máy tính) | mode=rasp (Raspberry) — cùng mã, khác cấu hình

[C-EVAL] fd_eval  (đánh giá)
  VAI TRÒ : đo tỷ lệ phát hiện đúng, báo sai, độ trễ, FPS thực, hành vi khi mạng yếu/mất kết nối
  LƯU Ý   : test cơ bản không đủ; bắt buộc có chạy liên tục + mạng yếu (G5)

======== QUY ƯỚC CHUNG ========
- Tên mã lỗi: E_<FD>_<LOẠI>. Mọi lỗi mang: trace_id, nodePath, ts, mô tả ngắn.
- Mọi component có hàm health() trả OK/DEGRADED/DOWN để fd_flow theo dõi.
- Thêm component mới: ghi vào file này + feature-map.md + logic.ts (NodeId) trước khi viết code.
